## Implementation and documentation facts

- Git history: first commit `b43a975` names the project **AgentBridge**. A later commit `a254de1` introduced a separate Sanskrit label in documentation and renamed module paths to `sutra`. The original commit and inspected history do not establish the exact original Sanskrit spelling; this report leaves it unspecified.
- Current package metadata is `sutra-local`; import package and CLI command are `sutra`. The CLI help text contains a stale unrelated product banner. This docs task does not alter package names, import paths, or CLI code.
- Supported CLI command names observed from help: `local`, `control-plane`, `dev-certificate`, `setup`, `status`, `workspace`, `projects`, `agents`, `doctor`, and `connectors`.
- Local runtime defaults to `127.0.0.1:8765`; control plane defaults to `127.0.0.1:8766` and requires an operator token plus TLS certificate/key. `setup` creates the runtime home directory and a development certificate (default output directory `.dev-certs`); the inspected command does not initialize the runtime database.
- Runtime home defaults to `~/.sutra`; `SUTRA_HOME` and legacy `AGENTBRIDGE_HOME` are read. The environment template's exact supported variables must be distinguished from speculative README claims.
- Telegram configuration is optional. The control-plane CLI reads `SUTRA_TELEGRAM_BOT_TOKEN`/`TELEGRAM_BOT_TOKEN`, allowlisted numeric user IDs, and polling/webhook configuration.
- Local/HTTP and stdio MCP connectors, GitHub REST/MCP and Supabase MCP are implemented in the current working tree and have mock/local tests. No live provider check was made in this run. Slack and Discord are not verified as working integrations and remain documented as planned.
- `LLM_PROVIDER`/Ollama integration appears in design docs, but no current runtime source path was found in the reviewed entry points. Do not describe it as a supported provider without additional evidence.
- The terminal connector validates its working directory and checks traversal text, but current code does not establish universal filesystem sandboxing for arbitrary child-process arguments. MCP resources/prompts bypass the tool policy/audit path in the reviewed implementation. These are documented limitations, not fixed in this documentation task.
- Archify v3 has five typed JSON diagram modes and command-line schema validation/rendering/delivery. The 41 existing diagram files use an incompatible legacy schema and have no declared HTML outputs present. Their IDs, schemas, and declared output paths were preserved; display labels and machine-specific repository metadata were corrected. The separate current-schema artifact passed Archify finalize and browser checks.
- The current-state architecture guide and standalone diagram distinguish local services from an optional configured external gateway. The longer `system_architecture.md` is explicitly labeled as historical proposal material, not a current implementation specification.
- Direct references to untracked connector implementation files are plain code paths, not links that would break in a clean checkout without those files.
- Documentation QA checked 67 Markdown files and 42 JSON sources: no broken local links or Markdown anchors, no JSON syntax errors, no machine-specific workspace paths, no prohibited product-label literals, and no high-confidence credential patterns. Mermaid rendering is not available; Mermaid blocks were syntax-reviewed only.
