# AgentBridge GitHub Actions & CI Visibility Architecture (Phase 6B.5)

## 1. Overview & Objective

Continuous Integration visibility is critical for mobile developers reviewing pull requests or verifying deployed changes. AgentBridge provides read-oriented and guarded control interfaces for **GitHub Actions** via Telegram without requiring access to a full desktop environment or IDE.

Key capabilities:
- Inspect recent workflow runs across the repository or filtered by branch/PR.
- Track workflow statuses (`queued`, `in_progress`, `completed`) and conclusions (`success`, `failure`, `cancelled`, `timed_out`).
- View bounded, tail-truncated workflow run logs with strict automated secret redaction.
- Safely trigger workflow run cancellations or reruns under strict `PermissionEngine` authorization.

## 3. Log Retrieval & Safety Guardrails

Workflow logs generated by CI pipelines can easily span hundreds of thousands of lines and several megabytes. Directly forwarding these to Telegram would exceed platform message limits, waste mobile bandwidth, and risk leaking sensitive build secrets.

### 3.1 Bounded Retrieval & Tail Truncation
- CI logs retrieved via `get_workflow_run_logs` are limited by `max_lines` (default: 80 lines).
- Logs are extracted using tail-oriented slicing (the final lines of a build job usually contain the decisive failure reason or test crash traceback).
- If the log exceeds bounds, an explicit truncation header is displayed indicating total lines and the truncated subset.

### 3.2 Automated Secret Redaction
- Before any log content is formatted for Telegram delivery, it passes through `sutra.redaction.redact_secrets`.
- All detected API keys, GitHub tokens (`ghp_*`, `github_pat_*`), AWS credentials, private RSA/ED25519 keys, and environment passwords are sanitised and replaced with `[REDACTED]`.

## 4. Workflow Run Control Guardrails

### 4.1 Rerun Workflow Run
- Endpoint: `POST /repos/{owner}/{repo}/actions/runs/{run_id}/rerun`
- Risk Tier: `HIGH`
- Protection:
  - Requires operator confirmation in Telegram ChatOps.
  - AgentBridge does **NOT** automatically rerun failed jobs based on AI speculation.
  - Protected against double-click repetition via idempotent state locks.

### 4.2 Cancel Workflow Run
- Endpoint: `POST /repos/{owner}/{repo}/actions/runs/{run_id}/cancel`
- Risk Tier: `HIGH`
- Protection:
  - Requires explicit real-time operator authorization.
  - Verifies that the workflow is actively running (`status in ("in_progress", "queued")`) before dispatching cancel call.

## 5. CI-Aware PR Integration

PR inspection screens automatically correlate active workflow runs for the PR's source branch (`head_branch`). Developers can instantly assess whether a PR is healthy, in-progress, or failing directly from the PR overview screen:

```
⚙️ CI Status:
  ✅ Build & Test (main)
  🟡 Security Scan (feature/auth)
  ❌ Lint Checks (feature/auth)
```
